## 为什么上一版可能停在 0.958 左右

1. Flight Distance 既有连续含义，也可能充当隐含航程标识。128/127 桶直方图合并大量不同距离，原始字段置换的重要性也会受模型表达方式影响。
2. 第一轮的均分、延误比率、服务交叉多是原字段的重表达；航程群体画像与外部原始调查 teacher 带来的信号不同。
3. 三种树的等权融合误差高度相关；RealMLP、TabM、TabPFN、TabICL 等公开 OOF 能补充预测方式。
4. 大量相关 OOF 用无约束线性权重容易过拟合。作者使用未标准化 logit、L2 正则 C=0.003；相关性很高并不自动意味着必须删列。

## 实验协议

- 保留第一轮文件，新增 `artifacts_v2/` 与 `submission_v2.csv`。源数据不改写。
- 所有训练、矩阵分析和推理通过 Slurm Compute Node；沿用项目 `.venv`。下载属于文件 I/O，不在 Head Node 训练。
- 独立重训特征实验：固定新的开发划分，训练部分内部再分 early stopping 集；外层评估标签不进入 teacher、目标编码、early stopping 或梯度训练。由于上一轮已使用整套数据进行开发，新划分仍属于重复使用数据的开发证据，不能恢复成全新独立测试。
- 航程均值/频数可以使用 train+test 的无标签字段，这是明确记录的 transductive 特征；目标编码严格仅由当前拟合分区标签产生，训练行再内层交叉编码。
- 原始调查数据先核查与比赛行的特征重合；teacher 只读原始调查标签，单独保存模型、数据版本、指纹和预测。
- 公共 OOF：带 id 的文件按 id 对齐；无 id 文件验证尺寸、有限性和作者声明的 train/test 行序，保存这一限制。不把高 AUC 当作行序证明。核查部分文件自带的 y、fold、id。
- 概率统一转 logit，原已为 logit 的列保持原表示，训练/测试使用同一种变换。所有列和来源都列入 manifest；缺失成员或异常形状直接失败，不静默跳过。
- 五折元模型 CV 用 seed 7 复现作者，比较 182/211/228、C 的小范围选择与关键模型组消融。随后用第二个元模型种子检查结论稳定性。
- 这里的公共 OOF stacking 分数称为“元模型 CV”。它不等于重训全部基模型的严格嵌套 CV：各来源基模型划分不同，元模型训练行的基预测可能利用过元验证行标签；部分公开模型也用自身验证折早停。公共开发决策和榜单选择还带来适应性偏差。因此不可将 0.9622 本地 CV 当成已达到 0.9618 公开榜的证明。
- 只输出连续预测，不调分类阈值。AUC 衡量排序，0.5 准确率不是比赛目标。

## 本轮优先级

1. 复现 228 个公开基预测上的逻辑回归，先形成完整、可提交的改进候选。
2. 实际检验航程分箱/类别化、航程画像、原始 teacher、交叉目标编码，并比较树家族。
3. 比较基模型误差互补和元模型消融，保留稳定增益；归档无效尝试。
4. 重载保存的模型重建预测，检查 299,844 行、id 顺序、概率范围、SHA-256 和差异，交付推荐提交与中文结果报告。
